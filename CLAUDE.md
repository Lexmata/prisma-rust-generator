# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Prisma generator (Node/TypeScript) that emits ORM-agnostic Rust types from a Prisma schema: model structs, enums, filters, and the full Prisma input surface (`Where`, `WhereUnique`, `OrderBy`, `Select`, `Include`, `Create*`, `Update*`, nested-relation inputs, scalar field-update ops, aggregation inputs). It runs as a child process of `prisma generate`, reading DMMF from stdin and writing `.rs` files. See README.md for consumer-facing usage and the generated shape.

## Commands

```bash
pnpm build              # tsc -p tsconfig.json → dist/
pnpm dev                # tsc --watch
pnpm typecheck          # tsc --noEmit
pnpm lint               # eslint src test --max-warnings=0
pnpm test               # vitest run (full suite; ~75s with the stress e2e)
pnpm test:watch         # vitest in watch mode
pnpm test -- <pattern>  # run a subset (e.g. pnpm test -- 14-stress)
pnpm test:rust          # bash scripts/verify-rust.sh — cargo fmt/clippy/check across every test/compile/* fixture
```

To run a single test file: `pnpm vitest run test/path/to/file.test.ts`.

To regenerate a fixture's Rust output without running the cargo phase, run the file's e2e test — `runFixture()` writes to `test/compile/<id>/src/`. The slow part of `pnpm test` is `cargo check`/`clippy` on the `14-stress` fixture (~73s); everything else is sub-second.

## Pipeline

```
DMMF (from @prisma/internals) → IR → emit → write → rustfmt → prune stale files
```

- **DMMF → IR**: `src/ir/build.ts` consumes Prisma's DMMF plus a regex-built file map (`src/ir/file-map.ts`) that records which `.prisma` file each model/enum came from. The IR (`src/ir/types.ts`) is the normalized layer between Prisma and the emitter — `ModelIR`, `EnumIR`, `FieldIR`, `RelationIR`, `RustTypeRef`. Cross-link relations, compute Eq-eligibility (`src/ir/eq-eligibility.ts` — reverse-graph BFS), detect input cycles (`src/ir/cycles.ts` — Tarjan's SCC).
- **IR → emit**: Each emitter is pure: takes an IR node + options, returns a Rust source string via `RustWriter`. Emitters live under `src/emit/`:
  - `model.ts` — struct definitions
  - `enums.ts` — enums + per-enum `*FieldUpdateOperationsInput`
  - `filters/` — `WhereInput`, scalar/enum/relation filter modules
  - `inputs/` — the full Prisma input surface
  - `shared/common.ts` — `QueryMode`, `SortOrder`, `OneOrMany<T>`
  - `type-ref.ts` — module-path resolution for cross-module references
- **Emit → write**: One of three layouts (`src/layout/{per-file,per-model,single}.ts`) orchestrates emitters into named files. `per-file` (default) mirrors the source `.prisma` file structure. Writes go through `src/parallel/pool.ts` for bounded concurrency. `src/generate.ts` is the top-level orchestrator.
- **Rustfmt**: `src/fmt.ts` runs `rustfmt` over the output in shards. The e2e harness (`test/e2e/run-fixture.ts`) also runs rustfmt as a post-process so emitter formatting nits don't cause `cargo fmt --check` failures.
- **Prune**: `src/prune.ts` removes stale `.rs` files. Gated on a `@generated by prisma-rust-generator` marker — only files we wrote get deleted.

## Key conventions

### Module-path routing in nested inputs

Nested input types come in two flavors, and they live in different modules:

- **Per-relation types** (`{Target}CreateNestedOneWithout{Source}{RelField}Input`, `*UpdateWithout*Input`, etc.) — emitted from the *source* model's perspective and live in the source's module. Use `ctx.prefix` in `src/emit/inputs/nested.ts`.
- **Global per-model types** (`{Target}WhereInput`, `{Target}WhereUniqueInput`, `{Target}ScalarWhereInput`, `{Target}UpdateManyMutationInput`) — emitted once per model in its own module. Use `ctx.targetPrefix`.

Getting this wrong produces `cannot find type X in module crate::Y` errors at compile time.

### Disambiguating nested-input names

A single model can have multiple relations to the same target (e.g., `CaseTask.creator: User` and `CaseTask.assignee: User`). The `relSuffix` cached on `Ctx` (= `${source.name}${toPascalCase(relation.prismaName)}`) is appended to nested-type names to keep them unique. Always reference `ctx.relSuffix`, never recompute.

### Box-wrapping and recursion limit

Top-level `*CreateInput`/`*UpdateInput` relation fields, and the inner relation fields inside `CreateWithout`/`UpdateWithout` bodies, are wrapped in `Option<Box<...>>`. The generated `lib.rs` carries `#![recursion_limit = "1024"]` (constant in `src/layout/header.ts`). Both are required together for densely connected schemas — Box alone doesn't break drop-check recursion, and recursion_limit alone doesn't fix compile-time size cycles. Don't drop either.

### Identifier sanitization

All identifiers flowing into generated Rust go through `src/ir/names.ts` (`toSnakeCase`, `toPascalCase`, `rustFieldIdent`) and `src/ir/file-map.ts` (`normalizeStem` — converts file stems to valid Rust module names). Prisma names are mostly safe but file stems like `case-processing.prisma` must become `case_processing`. Never bypass these helpers.

### Eq-eligibility

A model is `Eq`-derivable iff its scalars are all Eq AND every relation target is Eq-eligible. Computed once via reverse-graph BFS in `src/ir/eq-eligibility.ts`. Models containing `f32`, `f64`, or `Decimal` are ineligible and the ineligibility propagates.

### CommonJS interop for @prisma packages

Both `@prisma/generator-helper` and `@prisma/internals` are CJS and don't export named ESM exports. Use the default-import-and-destructure pattern:

```typescript
import helper from "@prisma/generator-helper";
const { generatorHandler } = helper as { generatorHandler: typeof import("@prisma/generator-helper").generatorHandler };
```

Named imports compile but fail at runtime.

### Config defaults

`src/options.ts` parses `GeneratorOptions` into `GeneratorConfig`. Defaults: `outputLayout: per-file`, `dateTimeCrate: chrono`, `decimalCrate: rust_decimal`, `bytesCrate: std`, `jsonCrate: serde_json`, `serde: true`, `runRustfmt: true`. Tests share `DEFAULT_CFG` in `test/e2e/run-fixture.ts`.

## Generated-output guarantees

Every test fixture in `test/compile/*` must pass `cargo fmt --check`, `cargo clippy -- -D warnings`, and `cargo check`. The clippy allow-list is intentionally narrow (`clippy::upper_case_acronyms`, `dead_code`) — anything else has to be addressed in the emitter, not allowed away. Pedantic/nursery/restriction lint groups are out of scope.

The `14-stress` fixture (`test/fixtures/14-stress/`) is the canonical stress test: 17 `.prisma` files, ~75 models, hundreds of relations. It's name-anonymized synthetic output produced by `scripts/anonymize-stress-fixture.mjs`. If a change breaks it, it's a regression — don't skip the test.

## Output-format stability

Pre-1.0 — emission format may change between minor versions. User-visible output changes go in `CHANGELOG.md` under `## Unreleased` with a one-line migration note. After 1.0, any output change is a major-version bump.

## Common pitfalls

- **Stale generated files**: `test/compile/<id>/src/*.rs` is regenerated by the test runner. Don't hand-edit; your changes will be overwritten on next run.
- **Rustfmt diff in tests**: the e2e harness runs rustfmt post-process, but if the emitter produces output that rustfmt can't parse (e.g., invalid Rust), the test will fail with a confusing message. Read the actual generated `.rs` file to diagnose.
- **`cfg.serde = false` is rarely exercised**: most fixtures default to `serde: true`. If you change emitter logic that touches serde derives or attributes, add a unit test with `serde: false` (see `test/emit/scalar-where.test.ts` and `test/emit/create-update.test.ts` for the pattern).
- **Adding to `ctx.prefix` vs `ctx.targetPrefix` in nested.ts**: trace whether the type you're referencing is emitted per-(source,relation) or per-target-model. The path resolution depends on which module the referenced type lives in.
